# 相声家谱：main 合并后的开发路线与效果验收

更新：2026-09-11。执行基线：3D 场景实现提交 `71e4c8d` 与同批合并的文档。本文描述接下来要做的工作，不表示这些效果已经完成。用户已要求将开发分支合并到 main；合并属于开发基线整合，不等于发布上线或视觉验收通过。

## 一、现状与目标

视觉基准为 [已确认双视图设计稿](design/immersive-approved.webp)：上屏「岁月入画」，下屏「一脉千枝」。保持淡墨青灰、宣纸暖白、少量朱砂、清晰中文排版。

| 范围 | 已有实现 | 仍需完成 |
| --- | --- | --- |
| 时间长卷 | Three.js 曲面与厚度、事件书笺、GSAP 镜头推进、固定详情 | GPU 对稿、书笺遮挡、场景密度、推进手感 |
| 立体谱系 | 球形节点、三维曲线、字辈分层、分支展开、平面入口 | 密集排布、稳定局部展开、连线方向反馈、微缩地图 |
| 山水环境 | 真实 alpha 山景平面、全景天空球、雾与基础光照 | 白边、接缝、多套近中远景、纸面材质、透明排序 |
| 查阅方式 | 长卷、谱系、人物书笺、年表及来源 | 视角切换后的阅读位置连续性、分享状态、触控 |
| 数据 | 119 人、105 条师承、25 条来源、11 条正式事件 | 原有资料复核、未关联事件的人物、作品与组织履历 |
| 验证 | 基线 125 项测试；代码与生产构建通过 | 实际 GPU、设计稿对照、移动实机、浏览器差异与性能 |

注意：11 条正式事件主要覆盖 10 位人物，其余 109 人尚无正式事件关联；临时显示的生卒年不是已核验事件。详见 [数据覆盖说明](data-coverage.md)。当前山峦是三维场景中的透明平面，不是可以全角度绕行的完整山体网格；天空为穹顶全景映射，不是 HDRI 或六面天空盒。

## 三、M0：先建立真实 GPU 验收基线

**期望效果：** 浏览器确实显示三维长卷、半透明山峦与节点连线；测试画面与用户实际看到的画面一致。

步骤：

1. 从最新 main 新建任务分支，在支持 WebGL 的 Chrome/Edge 和 Safari 中运行生产预览。优先使用现有 MacBook Pro/Mac mini；Windows 工作站做第二环境。不要把云浏览器的简化预览当成 GPU 验收。
2. 记录浏览器版本、系统、GPU、DPR、窗口尺寸、提交 SHA；查看 WebGL 是否初始化成功及控制台错误。
3. 固定人物与事件状态：侯宝林默认一脉、马季展开传人、全谱 119 人、全部纪事首/中/末事件、争议事件与出处展开。
4. 分别录制首次加载、左右拖动、连续切换十次、展开/收起支系、切换视图、窗口缩放、恢复前台。
5. 把生成稿上下屏分别作为参考；在同宽高比下对照构图、文字层次、右侧详情、近中远景与遮挡。先修 P0/P1，再修 P2。
6. 更新根目录 `design-qa.md`；在实际对稿通过前保持 `blocked` 或 `failed`，不把单元测试成功写成视觉通过。

建议观测尺寸：1440×900、1920×1080、390×844；这些是测试窗口，不要求强行改变原稿比例。

主要文件：`src/components/InkWorld.tsx`、`SpatialTree.tsx`、`TimelineJourney.tsx`、`design-qa.md`。

验收：有完整的 GPU 截图与录屏；无黑屏或渲染器初始化异常；所有标为已验证的结果可由同一提交复现。

## 四、M1：把水墨素材变成可信的空间环境

**期望效果：** 近处松石清晰，中景青灰山峦有层次，远山融入薄雾，天空与宣纸色自然衔接。轻移鼠标时各层产生不同幅度的视差，静止阅读时画面安定。

步骤：

1. 将背景分为天空、远山、中山、近景松枝/岩石、局部薄雾五类素材；每张记录生成来源、尺寸、透明范围与实际用途。近中远景应有不同轮廓，避免同一山峰重复成阵列。
2. 优先解决现有山脊白边。逐张在白、灰、深色底上检查 alpha；拒绝烘焙棋盘格的 RGB 图。保留原始素材，修正版另存，验证后再替换。
3. 按原始宽高比放置平面；让远山更淡、更大、更远，近景只占边缘，避免遮盖事件和人物。先使用受控相机范围，防止看到贴片侧面或背面。
4. 检查天空全景左右接缝、极点拉伸和相机移动；若穹顶映射无法消除可见问题，再生成匹配的六面天空盒。除非材质确有需求，不必引入大体积 HDRI。
5. 检查透明层排序、`alphaTest`、`depthWrite` 与雾的组合；防止近景突然消失、黑边、透明面相互切割。按实际画面决定是否增加独立雾层，不默认堆叠大量半透明面。
6. 为纸面补充轻微纤维与粗糙度纹理，保持可读性；控制厚度边缘、卷曲高光和阴影。灯光统一来自一个主方向，不使用抢眼金属反射。
7. 评估雾层/纹理分辨率/透明过绘的成本，再决定是否引入 KTX2 压缩和按需加载。

验收：静止截图无明显白边、重复轮廓、可见天空接缝；镜头全行程不露场景边界；背景细节不压过文字。透明素材校验与真实合成画面都通过。

主要文件：`public/assets/spatial/`、`InkWorld.tsx`、`ink-world.css`；需要时拆分独立 `InkEnvironment` 模块，避免继续扩大单一运行时文件。

## 五、M2：时间轴做到“沿卷进入历史”

**期望效果：** 选中事件在前景清晰展示，沿长卷能看到后续事件；用户始终知道自己从哪里来到哪里。转场过程中日期与详情明确对应，不出现旧详情配新画面。

步骤：

1. 依据 GPU 截图标定 S 形主轴、卷面宽度、相机高度、视野角与前景书笺比例。先固定 3–5 个关键机位，再插值形成连续路线。
2. 将相机位置、视线目标与卷面参数统一到路径进度；进度变化应有明确加速、巡航、减速过程。短距离比长距离更快，跳转跨度大时避免过长飞行。
3. 当前 1150ms 作为初始调参基线，不当作最终手感。目标是即时反馈、可中断、快速连点无排队。拖动直接跟手，松手后吸附到合理事件。
4. 实测书笺与锚点的投影。当前事件保留标题、日期、状态；远处采用更简洁层级。处理遮挡时优先调整空间排布与信息密度，不让用户追逐漂移文字。
5. 连线准确落到同一事件的卷面锚点，补充日期刻度；如果仍按序号排布，必须继续注明间距不代表时长。后续可另加“真实时间比例”模式，并对同年密集事件做聚合。
6. 固定右侧详情区，保留出处、不同说法、事件关联人物。切换范围/事件类型时明确新位置与结果数量；空结果可清除筛选。
7. 增加事件专属 URL 状态、上一/下一段、起点/终点、当前位置概览；键盘和触屏可执行同一套动作。

验收场景：从第一条到最后一条、跨越多个事件、快速往返、只有一条/零条事件、争议详情展开、减少动态效果、浏览器返回。每次事件 ID、日期、选中书笺和右侧来源一致。

主要文件：`src/lib/immersive-space.ts`、`TimelineJourney.tsx`、`InkWorld.tsx`、`TimelineView.tsx`。

## 六、M3：谱系做到“看清主干，再展开支系”

**期望效果：** 朱砂路径一眼可追踪，支系展开有方向和顺序；字辈分层有纵深，但名字保持足够大、稳定、容易选中。

步骤：

1. 先区分“实际师承代数”和“德寿宝文明字辈”。无明确字辈的人物仍可按师承拓扑排列，不强行赋予字辈；多师承和有争议的边独立处理。
2. 保持稳定节点 ID 与坐标缓存。展开传人时尽量只调整相关局部；不要重新随机布局整张图，也不要因选择人物反复重建 GPU 上下文。
3. 制定前景选中节点、祖师路径、直属传人、其他支系四级显示规则；背景淡化必须同时保留文字状态，不能只靠颜色表达争议。
4. 展开顺序：先显示将展开的范围 → 连线沿师傅到徒弟延伸 → 子节点出现 → 标签稳定。收起顺序反向执行，收起后焦点回到父节点。
5. 做屏幕空间标签碰撞检测。优先扩大行距/支系间距，再采用可展开聚合；不能简单隐藏所有重叠人物。提供放大到可读尺寸的操作。
6. 悬停只做轻微强调与相邻路径提示，不改变点击目标中心。相机聚焦保持上下文，避免过度旋转和突然翻面。
7. 新增可点击微缩地图：显示全谱边界、视口框和当前人物；拖动视口框平移，点击支系聚焦，与已有缩放/适应按钮互通。
8. 完善关系详情：师承依据、争议说明、拜师/受教时间精度；组织退出、除名、暂停演出作为独立事件，不能抹掉历史师承。

验收场景：侯宝林→马季、马季全部传人、另一主支、全谱、字辈筛选、姓名搜索、多师承、争议边。当前人物应可定位，点击命中稳定，展开/收起后数量正确；GPU 渲染仍复用上下文。

主要文件：`src/lib/atlas.ts`、`SpatialTree.tsx`、`AtlasGraph.tsx`、`InkWorld.tsx`、关系数据文件。

## 七、M4：让四种阅法串成一个完整产品

**期望效果：** 从谱系点开人物书笺，再进年表、查看争议或回到长卷，始终围绕同一个人，返回后仍在原来的位置。

步骤：

1. 明确统一阅读状态：人物 ID、视图、事件 ID、查询、字辈、展开支系、相机位置。区分应写入 URL 的分享状态与仅需本地保留的临时状态。
2. 切换视图保留选中人物、筛选和合理的相机位置；返回按钮、浏览器前进/后退与直接打开深链接行为一致。
3. 先完成清晰的出入场顺序，再打磨书笺翻页、墨色路径显现等细节。页面内容必须在动画期间保持可读、可操作。
4. 为合法获取的人像增加来源与授权记录，缺图沿用姓名印记。不要把生成的拟真人像冒充历史照片。
5. 建立作品独立记录：标题、作者/整理者、演出者、版本、年份精度、来源、可用外链。区分创作与代表演出，不默认托管受版权保护的音视频。
6. 补充关系比较入口，例如同时查看两人共同祖师或师承路径；复杂功能排在基本阅读连续性之后。

验收：从分享链接进入、搜索改人、展开书笺、转到事件、查看来源、返回谱系，人物/事件与位置不串线；来源链接和空状态全部有效。

## 八、M5：触控、性能和可访问性

**期望效果：** 高性能设备呈现完整空间，普通设备也能稳定查谱。画面效果根据能力减少，资料与操作入口不减少。

步骤：

1. 建立高/中/低三档：DPR、纹理分辨率、透明层数量、抗锯齿、雾层和阴影；允许手动切换，避免档位自动反复跳动。
2. 触控单指拖动、双指缩放与页面滚动分区明确。事件卡和缩放按钮至少提供约 44×44 CSS px 可触区域；拖动结束不误触人物。
3. 为减少动态效果提供直接定位与静止阅读，保留键盘访问；隐藏节点不能陷入 Tab 焦点，侧栏展开有明确焦点路径。
4. 批量复用几何、材质、纹理；按需渲染，隐藏视图暂停，节点更新不要反复载入同一环境。用内存记录验证卸载后回收。
5. 实测透明过绘与标签 DOM 数量；必要时仅让近景使用完整标签，远景聚合并提供可发现的放大入口。
6. 建立 Chrome/Edge、Safari、iOS Safari、Android Chrome 的核心用例表；测试 GPU context lost、资源失败、后台恢复、窗口旋转。

初始性能目标（目标不是已测结果）：桌面目标 60 FPS；移动最低档关键拖动目标 30 FPS；交互反馈约 100ms 内；连续切换视图 30 次内存不持续攀升。报告需标明设备、场景人数、档位、加载缓存状态和测量方法，无法达到时先降低特效再调整目标。

## 九、M6：史料按批扩充，而不是堆名单

**期望效果：** 用户既能追师承，也能查个人成就、作品、组织变动和公开争议；每项结论都能知道依据是什么。

步骤：

1. 复核现有 119 人与 105 条师承：识别孤立人物、多师承、姓名别名、辈分未知和旧书目仅有名称却缺页码的问题，建立逐条待核验队列。
2. 优先补齐已展开主脉人物的生平事件，随后按时代与地域扩展；不要让全库持续只围绕德云社争议。
3. 每批建议 10–20 位人物或 15–30 条事件，数量是工作包上限，不是必须填满的指标。完成资料检索、原文阅读、入库、关系检查、页面核对后再提交。
4. 师承依据优先查正式传记、曲艺史料、原始采访和可归因的官方资料；单一二手来源须标明范围，不推断其未支持的事实。
5. 明确区分组织退出、师门/家谱除名、劳动关系变化、演出暂停、行政处罚和公开争议；记录日期精度与事件参与方，避免相互替代。
6. 对争议建立具名观点、原文出处、发表时间和来源之间的分歧；“某人公开说了什么”与“他说的内容已经证实”分别处理。无来源的传闻不作为确定事实上线。
7. 出生/逝世/作品条目分别核验，补充后更新覆盖统计；已有临时生卒年只有在证据足够时转为正式事件。
8. 新增公开纠错入口前，先完善数据贡献说明和 PR 模板：修改理由、支持原文、事实/说法/争议状态、关联数据与测试结果。

每批交付：来源清单、修改的数据、未解决分歧、覆盖统计变化、对应页面截图与测试记录。测试验证结构和引用完整性，不替代史实核验。

## 十、M7：最后做视觉收口与发布准备

1. 对两张批准稿逐项比较构图、山水层次、宣纸质感、节点大小、字体、详情宽度和底部导航；统一不同视图的色彩、间距与运动节奏。
2. 录制一条完整演示：进入主脉→展开传人→点人物→进入年表→沿卷前行→打开出处→回到谱系。出现可见卡顿或定位不清，先修复再录制。
3. 完成图像授权、来源说明、网站元数据、分享预览、错误页和深链接刷新；验证部署平台的路由回退与缓存策略。
4. 只有视觉、资料与性能门槛通过后，才将 QA 改为 passed。FWA 作为设计追求，不写成已经获得或保证获奖。
5. 发布前固定 Git 标签/提交与构建产物，保留上一个可用版本；用户明确要求发布时再部署。main 合并本身不等于发布授权。

## 十一、每个小里程碑的固定流程

1. 从最新 main 建独立任务分支，只做一个可审查目标。
2. 记录要改变的画面、操作和验收条件；使用本文件的阶段编号，例如 M2-02。
3. 先完成实现及相关素材，再跑必要的逻辑/交互测试、构建与 GPU 对照；数据批次另附原文核验记录。
4. 修复失败项目，更新 `docs/progress.md`、QA 与已完成清单，再提交 Git、同步远端并创建 PR。
5. PR 写清用户能看到的变化、依据和已知限制；合并前验证待合并的具体提交，不混用旧测试结果。
6. 未经明确授权不发布；合并沿用用户在当前任务中的明确指令，不为后续所有 PR 自动假定无限授权。
